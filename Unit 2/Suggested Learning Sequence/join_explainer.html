What does a JOIN actually do?

Your events table only stores a device_id number — not a room name. A JOIN is how a query gets the readable room name back, without storing it twice.

Lesson 12SELECT, JOIN, GROUP BY
Where this fits: Lesson 12 asks you to "write a JOIN query linking events to devices." This page walks through what that actually means before you write your own.

Start with something you already use

📱

Your phone's call log doesn't store people's names — it only stores phone numbers. Your Contacts app is what stores the name that belongs to each number. When you open Recents and see "Mum" instead of a string of digits, your phone quietly matched the number in your call log against the number in your contacts, and stitched the two together.

That matching-and-stitching step is exactly what a JOIN does in a database — except instead of phone numbers, our database matches device_id.

A worked example

This is the shape of query you'll write for Lesson 12 — joining events to devices so a room name comes back instead of a raw id:

SELECT events.event_id, devices.room, devices.location_name, events.event_timestamp, events.classification, events.amplitude FROM events JOIN devices ON events.device_id = devices.device_id WHERE devices.room = ? ORDER BY events.event_timestamp
SELECTWhich columns end up in the result — notice devices.room sits right alongside events columns, even though it came from a different table.
FROMThe table you're starting from — the "many" side, one row per event.
JOIN … ONThe matching rule. events.device_id = devices.device_id is exactly the green lines in the diagram above — pair up rows where these two numbers agree.
WHEREFilters the joined result, same as it would on a single table — here, only keep rows for one room.

Three things to remember

  1. events stores device_id only — never room or location_name directly. That's the 3NF fix: no repeated text.
  2. JOIN matches rows using a shared column — here, device_id in both tables has to be equal.
  3. The result reads like one table, but the data actually came from two — nothing was duplicated in storage to make that happen.
